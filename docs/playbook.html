Renewal Risk Analyser & Router

One agent was the brief. The platform many agents plug into is the job. Everything below runs locally, from the repo.

3 agents on one bus 92 tests, eval-gated in CI champion claude-haiku-4.5, chosen on the eval one event → many agents

What it optimises for

Nothing trusted unchecked

Every figure the model cites is verified against real data. Invented numbers get the answer discarded.

Explainable to a non-engineer

Any run reads back in plain English in seconds, from the same trace an engineer debugs.

It fails to a human

Low confidence, model down, or budget hit: work routes to a person. It never silently stops.

Run it  ·  use .venv/bin/python (or activate the venv first)

Run the supplied payload — 3 accounts, 3 drivers, 1 deduped redelivery — then every failure path
.venv/bin/python runner.py
Send one event → whichever agents subscribe. The source must match the payload's shape.
.venv/bin/python cli.py send gainsight samples/webhook_health_score_drop.json # health_score.dropped → renewal_risk .venv/bin/python cli.py send salesforce samples/webhook_renewal_approaching.json # renewal.approaching → renewal_risk .venv/bin/python cli.py send zendesk samples/webhook_support_spike.json # support.ticket_spike → support_escalation .venv/bin/python cli.py send gainsight samples/webhook_low_risk.json # low risk → skipped / held (the negative path)
Operate explain a run, audit the platform, gate a prompt change, open the dashboard
.venv/bin/python cli.py why <trace_id> # plain English + rules and values, from one trace .venv/bin/python cli.py audit # platform self-audit · exit 0 = no criticals .venv/bin/python cli.py eval --samples 3 # golden eval, gates on consistency not one lucky run .venv/bin/uvicorn app:app # dashboard on http://127.0.0.1:8000

Onboarding an agent

One command, and a second agent fires on the same event

Adding an agent is two files: its logic and one registry entry. Nothing that already exists changes.

  1. Onboard it. cli.py new-agent expansion_signal --owner denis --description "…" --subscribes-to health_score.dropped --tools salesforce gainsight slack
  2. It joins the registry. cli.py registry shows it owned, scoped to those tools, with a review date.
  3. One event fans out. a health_score.dropped event now runs renewal_risk and expansion_signal as two independent, fully-traced runs.
  4. It inherited everything. tracing, retries, idempotency, guardrails and tool permissions — written nowhere in the agent itself.

The new-agent contract  ·  wiring vs paperwork

FlagRoleWhat it does
namefunctional The id and module name. Must be import-safe (expansion_signal, not "Bad Name").
--subscribes-tofunctional Event types it listens for. This is the wiring — the bus fans events out by this list. Must be dotted.
--toolsfunctional Vendor access granted, and enforced. It can touch only these, nothing else.
--ownergovernance Who is accountable / who gets paged. Required — nothing runs unowned.
--descriptionmetadata One-line "what is this for." Shown in the registry and dashboard; no effect on behaviour.
--teammetadata Owning team label for grouping. Defaults to gtm-ai.

Worth a closer look

The biggest model wasn't the best

A bake-off over five models put claude-haiku-4.5 ahead of the larger sonnet-4.5 on accuracy and consistency at ~¼ the cost, stable across 240 runs. The champion is chosen on evidence, not reputation.

Hallucination is checkable by code

Evidence is metric/value pairs, verified against fetched data — deterministically, no second model judging the first. Grounding is 100% because ungrounded output never survives.

A single-run eval measures luck

Models flip drivers on ambiguous accounts between runs, so the eval samples each case many times and gates on consistency, not a single lucky pass.

The QA agent has no LLM, on purpose

Owner present, reviews on time, gate green: each has a correct answer. A model in the safety path makes a reliable result probabilistic and bills for it.

Running it — good to know

  • Interpreter. Use .venv/bin/python, or source .venv/bin/activate first. System python3 has no dependencies installed.
  • Source matches shape. A source that does not match the payload dead-letters with a reason — the negative path working, not a crash.
  • Idempotency. The same event_id twice is deduped. Re-fire with rm data/platform.db or a fresh id.
  • Live vs offline. By default it calls the model and records real spend. Prefix LLM_MODE=offline to run free on the deterministic analyser.
  • The audit may read WARN, by design. The health check flags an agent whose review is overdue — that is the review-cadence check doing its job, and it names the fix.

Honest limits: vendor clients are mocks over a fixture set; the BigQuery adapter's SQL is tested but never run against a live dataset; pseudonymising before the model call is minimisation, not anonymisation.
